# Internationalization (PL / EN) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Translate Quattro into Polish and English with `next-intl` and let users switch the language in Settings.

**Architecture:** Locale is resolved per request (`User.locale` → cookie → `Accept-Language` → `pl`) in `i18n/request.ts`; no URL prefixes. Messages live in `messages/{pl,en}.json` with typed keys. Components use `useTranslations` / `getTranslations`; dates and numbers use next-intl formatters; Clerk gets `plPL` / `enUS`.

**Tech Stack:** Next.js 15.5, React 19, next-intl 4, @clerk/nextjs + @clerk/localizations, Prisma 6, Vitest.

## Global Constraints

From [the spec](../specs/2026-10-21-i18n-design.md):

- Locales: `pl` (default) and `en`; cookie name `NEXT_LOCALE` (1 year, `path=/`, `sameSite=lax`); `User.locale String?` (null = no choice).
- Locale precedence: `User.locale` → cookie → `Accept-Language` (Polish → `pl`, anything else → `en`, no header → `pl`) → default `pl`.
- URLs have no locale prefix. `<html lang={locale}>`.
- `messages/pl.json` and `messages/en.json` have identical keys; Polish text is copied verbatim from the current code; English is a natural translation with the same ICU placeholders. Polish plurals use `one/few/many/other`.
- Message keys are typed from `pl.json` (`global.d.ts`, `AppConfig`).
- Not translated: domain/internal exception messages, DB values and enums (map them through message keys instead), console logs, webhook responses, user-generated content.
- `app/global-error.tsx` runs outside the layout/providers: fixed bilingual text, no next-intl.
- Dates/numbers use next-intl formatters, not fixed `dd.MM.yyyy` patterns.
- No other new dependencies besides `next-intl` and `@clerk/localizations`.

## Conventions (all translation tasks)

- Keys are camelCase, nested by namespace: `common`, `nav`, `system`, `dashboard`, `packages`, `reports`, `posts`, `admin`, `settings`, `locations`, `auth`, `errors`, `meta`. A task adds to the namespaces it needs in BOTH files at the same time; never leave one file behind.
- Server components: `const t = await getTranslations("ns")`; client components: `const t = useTranslations("ns")`. A shared component imported by both works without changes if it is a client component or only receives strings.
- Never build sentences by concatenating translated fragments; use one message with placeholders (`{name}`) or ICU plural/select.
- Enum/DB values stay in code; labels come from keys such as `reports.status.NEW`, `reports.type.DEFECT`, `admin.role.MANAGER`.
- Dates: client `const format = useFormatter(); format.dateTime(date, { day: "2-digit", month: "2-digit", year: "numeric" })` (add `hour: "2-digit", minute: "2-digit"` where time was shown); server `const format = await getFormatter()`.
- Page titles: `export async function generateMetadata() { const t = await getTranslations("meta"); return { title: t("packages") }; }` (the root template adds "| Quattro").
- Server actions: `const t = await getTranslations("errors")` (or the feature namespace) for returned messages.
- Existing tests with Polish fixture data stay untouched.

- [ ] **Step 3: Implement `i18n/locale.ts`**

```ts
export const LOCALES = ["pl", "en"] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = "pl";
export const LOCALE_COOKIE = "NEXT_LOCALE";

export function isLocale(value: unknown): value is Locale {
  return typeof value === "string" && (LOCALES as readonly string[]).includes(value);
}

// ponytail: looks only at the first tag and ignores q-weights; enough to pick pl vs en.
export function localeFromAcceptLanguage(header: string | null | undefined): Locale | undefined {
  const first = header?.split(",")[0]?.trim().toLowerCase();
  if (!first) return undefined;
  return /^pl(-|$)/.test(first) ? "pl" : "en";
}

export function resolveLocale(input: {
  userLocale?: string | null;
  cookie?: string | null;
  acceptLanguage?: string | null;
}): Locale {
  if (isLocale(input.userLocale)) return input.userLocale;
  if (isLocale(input.cookie)) return input.cookie;
  return localeFromAcceptLanguage(input.acceptLanguage) ?? DEFAULT_LOCALE;
}
```

```ts
import { describe, expect, it } from "vitest";
import pl from "@/messages/pl.json";
import en from "@/messages/en.json";

type Tree = { [key: string]: string | string[] | Tree };

function flatten(tree: Tree, prefix = ""): Record<string, string | string[]> {
  return Object.entries(tree).reduce<Record<string, string | string[]>>((acc, [key, value]) => {
    const path = prefix ? `${prefix}.${key}` : key;
    if (typeof value === "string" || Array.isArray(value)) acc[path] = value;
    else Object.assign(acc, flatten(value, path));
    return acc;
  }, {});
}

const placeholders = (s: string) =>
  [...s.matchAll(/\{(\w+)/g)].map((m) => m[1]).sort().join(",");

const plFlat = flatten(pl as Tree);
const enFlat = flatten(en as Tree);

describe("messages", () => {
  it("have the same keys in pl and en", () => {
    expect(Object.keys(enFlat).sort()).toEqual(Object.keys(plFlat).sort());
  });

  it("have no empty strings", () => {
    for (const [file, flat] of [["pl", plFlat], ["en", enFlat]] as const) {
      for (const [key, value] of Object.entries(flat)) {
        const items = Array.isArray(value) ? value : [value];
        for (const item of items) expect(item.trim(), `${file}:${key}`).not.toBe("");
      }
    }
  });

  it("use the same placeholders and array lengths in both languages", () => {
    for (const [key, plValue] of Object.entries(plFlat)) {
      const enValue = enFlat[key];
      if (Array.isArray(plValue)) {
        expect(Array.isArray(enValue) && enValue.length, key).toBe(plValue.length);
      } else {
        expect(placeholders(String(enValue)), key).toBe(placeholders(plValue));
      }
    }
  });
});
```

- [ ] **Step 7: `i18n/request.ts`**

```ts
import { cache } from "react";
import { cookies, headers } from "next/headers";
import { auth } from "@clerk/nextjs/server";
import { getRequestConfig } from "next-intl/server";
import prisma from "@/lib/prisma";
import { LOCALE_COOKIE, resolveLocale } from "./locale";

// ponytail: one indexed select per request for signed-in users; move the locale
// into the session object (getCurrentUser) if this ever shows up in profiles.
const savedLocale = cache(async () => {
  const { userId } = await auth();
  if (!userId) return null;
  const user = await prisma.user.findUnique({
    where: { clerkUserId: userId },
    select: { locale: true },
  });
  return user?.locale ?? null;
});

export default getRequestConfig(async () => {
  const [cookieStore, headerList, userLocale] = await Promise.all([
    cookies(),
    headers(),
    savedLocale(),
  ]);
  const locale = resolveLocale({
    userLocale,
    cookie: cookieStore.get(LOCALE_COOKIE)?.value,
    acceptLanguage: headerList.get("accept-language"),
  });
  return {
    locale,
    messages: (await import(`../messages/${locale}.json`)).default,
  };
});
```

- [ ] **Step 1: `actions/locale.ts`**

```ts
"use server";

import { cookies } from "next/headers";
import { revalidatePath } from "next/cache";
import { auth } from "@clerk/nextjs/server";
import prisma from "@/lib/prisma";
import { LOCALE_COOKIE, isLocale } from "@/i18n/locale";

export async function setLocaleAction(locale: string): Promise<{ success: boolean }> {
  if (!isLocale(locale)) return { success: false };

  (await cookies()).set(LOCALE_COOKIE, locale, {
    maxAge: 60 * 60 * 24 * 365,
    path: "/",
    sameSite: "lax",
  });

  const { userId } = await auth();
  if (userId) {
    await prisma.user.updateMany({ where: { clerkUserId: userId }, data: { locale } });
  }

  revalidatePath("/", "layout");
  return { success: true };
}
```
